# 配色方案 v2.1 · 科技盘（浅色）

> 这份文档是**设计决策记录**，不是调色笔记。每个色值都写着「为什么是这个」，
> 以及「不用它会怎样」。改色时请连理由一起改。
>
> **落地位置是三个文件，必须同步改**：`web/src/styles/tokens.css`（CSS 变量）、
> `web/src/utils/tokens.ts`（canvas/ECharts 读不到的 hex 副本）、
> `web/src/board/theme.ts`（大屏独立色板）。只改一处必然撞色。

## 0. 先说结论：上一版为什么还是不行

上一版（`docs/04-配色体检方案.md`）解决的是**合规**——把 8 处对比度不足压下去。
那只让页面「能看清」，没让它「好看」。真正的问题是三条：

| 问题 | 现象 | 根因 |
|---|---|---|
| **主色和蓝色预警撞了** | 主按钮、选中态、链接、蓝色预警看着像同一个东西 | 主色 `#2563EB` 与 `level.blue` 曾经**是同一个值**，靠语义区分是没用的，得靠色相 |
| **满屏一个色温** | 「清一色地白」，灰蓝渐变从导航一直铺到卡片 | 中性层只有明度差、**没有色相节奏**；页面底色是中性灰蓝，卡片是纯白，中间没有过渡层 |
| **信息色和装饰色不分** | 徽标、图标、强调条、数据条都在抢眼 | 没有「谁允许抢眼」的分级——四个预警等级已经用满了注意力预算，其他颜色必须退到低饱和 |

## 1. 方法：两个技能怎么用的

不是"参考了一下风格"，是按它们的规则反解色值：

**ui-ux-pro-max**（`npm i ui-ux-pro-max-cli` → `init --ai universal` → `scripts/search.py`）

- `--design-system "city flood monitoring early warning dashboard"` → 给出 PATTERN `Real-Time / Operations Landing`、STYLE `Glassmorphism`、深色盘、字体对 `Fira Code / Fira Sans`。
- **它的色板我们没采纳**：深色科技盘（`bg #0F172A`）与「整页不许有暗区」直接冲突。**采纳它的度量标准**：正文 4.5:1、图形 3:1、焦点可见、尊重 `prefers-reduced-motion`、实时数据必须标"何时更新"。
- `--domain style dimensional-layering` → 给了 4 级 elevation 与「层次靠 z-index 与阴影，不靠加颜色」。
- `--domain chart` → 三条硬规则：**不要只靠颜色编码**、比较类数据条按值降序、流式监控图要给当前值与状态文字。
- `--domain typography` → `Fira Code / Fira Sans`（Dashboard Data）。

**frontDesign**（`component-driven-frontend`，`PrayZhou/frontDesign`）

- `references/visual-language.md`：**玻璃只能用在「背后有可见深度、且这个表面代表一个层」的地方**；
  玻璃面必须包含「不透明兜底」；**永远不要让文案的可读性依赖背景图**。
- `references/premium-craft.md` 的「显廉价清单」直接命中我们：**三个互相竞争的强调色、发光光晕、每个卡片都上玻璃**。
  同页还给了一条有用的尺子：**三级圆角 + 三级阴影**。

## 2. 色相节奏：这是「不那么白」的关键

页面按**色温**分三层，而不是按明度分三层：

```
第 1 层  侧栏/导航      深藏青   #16304A   ← 唯一的深色面，锚住左上角
第 2 层  页面底         冷白     #F2F7FC   ← 带 0.5% 蓝的青白，不是灰
第 3 层  卡片           纯白     #FFFFFF   ← 只有承载数据的面才配纯白
```

三层之间用**色相**拉开（210° → 205° → 无彩），所以叠在一起时眼睛能分出前后，
即使把它们都去掉阴影、去掉圆角，层次依然在。这条是 `dimensional-layering`
「层次不靠加颜色」的正面用法：**靠色温和明度，不靠加色块**。

### 为什么不是深色科技盘

ui-ux-pro-max 给的推荐盘是深色（`bg #0F172A` + `#22C55E` 强调），这也是大屏的常见做法。
**这一版没有采纳它的色值，但把「科技感」换了个方式实现：**

| 深色科技盘的做法 | 我们的替代 | 为什么 |
|---|---|---|
| 压暗底色制造纵深 | **冷色骨架 + 三段色温** | 值班页面要长时间盯着看，暗底反白在日光灯环境下对比过强；且明确要求「整页不要暗区」 |
| 霓虹青/绿发光 | **青色主色 + 精确细线** | 发光光晕被 frontDesign 列为「显廉价」信号；青在浅底上依然读得出科技感 |
| 深色卡片 | **纯白卡片 + 三级投影** | 卡片是用来读数字的，长时间阅读浅底深字更省力 |
| 强调色满屏 | **只有预警四档允许高饱和** | 注意力预算有限，四档预警已经用满 |

一句话：**科技感来自「冷、准、有层次」，不来自「暗」**。
侧栏从原来的近黑 `#0F172A` 提到 `#16304A`，就是为了「不要过深」。

## 3. 主色换色相：从蓝改青

| | 旧 | 新 | 理由 |
|---|---|---|---|
| 主色 primary | `#2563EB` | **`#0E7490`** | 旧值与 `level.blue` **同值**，主按钮与蓝色预警无法区分。新值色相 192°，蓝色预警 205°，**拉开 7.5°**，且白字对比度 5.36 |
| 主色 hover | `#1D4ED8` | **`#0B5A70`** | 同色相压深，不用第二个色相（避免"三个强调色"） |
| 智能体系列 | `#0E7490` | **`#5B21B6`** | 原来和预测线、主色三个人挤在一个色相里；紫是"模型/推断"的通用语义，且与红橙黄蓝四档都拉得开 |

**这条是本次最关键的改动。** 一个系统里"主色"必须和"状态色"分开——主色代表
「可操作」，状态色代表「事实」。同色就等于告诉用户"点这里可以改变预警"。

## 4. 四级预警：surface 与 ink 分两轨

这是**两套值，不是一个值的深浅**：

| 等级 | surface（图形 3:1） | ink（文字 4.5:1） | weak（底） |
|---|---|---|---|
| 蓝 | `#0284C7` | `#0273AE` | `#E7F3FB` |
| 黄 | `#C08A00` | `#8E6600` | `#FBF3E0` |
| 橙 | `#EA580C` | `#BD470A` | `#FCEDE4` |
| 红 | `#DC2626` | `#D22222` | `#FCE9E9` |
| 无 | `#8497A6` | `#5C7080` | `#EDF2F6` |

**为什么必须分轨**：地图气泡、色带、圆环、条形是**图形**，阈值 3:1 就够，颜色要鲜；
标签文字是**正文**，要 4.5:1，必须更深。用一个值两边凑，结果一定是「图形不够醒目、
文字不够清楚」——这正是上一版改了 ink 却没改 surface 的遗留问题。

**黄与橙的色相间距被专门拉到 22.6°**（原来只有 11.6°）。三级预警是最容易被误读的一对：
用户看到"黄色变橙色"要知道严重程度**变了**。

**冗余编码**（`--domain chart` 的硬要求）：颜色只是**最低**一层编码。每个等级同时带
文字（「红色预警」）、形状/位置（气泡大小）、数值（`0.87 m`）。色盲用户不依赖颜色也能读。

## 5. 中性文本三级

| 级 | 值 | 用途 | 对比度 |
|---|---|---|---|
| ink1 | `#0B2545` | 正文、数值 | 15.4 |
| ink2 | `#4D7191` | 次级说明、表头 | 5.14 |
| ink3 | `#5C6F7F` | 时间戳、单位、脚注 | 4.83（页底）/ 4.56（次级底） |

三级文字**在三种底上都要过 4.5**，所以取值由最差的那个底（`#E9F1F9`）决定的。
上一版 ink3 用 `#94a3b8` 只有 2.56 —— 时间戳是真实内容，不是装饰，不能拿它凑。

## 6. 数据系列色（图表专用）

| 系列 | 值 | 说明 |
|---|---|---|
| 实测 | `#0B2545` | 墨色，与正文同色——实测是事实的基准线 |
| 预测 | `#6D28D9` | 紫，代表"未发生"；虚线 + 带状区间冗余 |
| 降雨 | `#2E86C1` | 青蓝，柱状；与主色青**同族不同明度**，因为它们本来就是一类物理量 |
| 修正 | `#B45309` | 赭色，只在图例一处分里出现 |

## 7. 层次与形状（frontDesign 的两把尺子）

**三级阴影**（不是四级——`premium-craft` 说四级起就廉价）：

```css
--elev-1: 0 1px 2px rgba(11,37,69,0.06);                                  /* 贴地：表头、行 */
--elev-2: 0 2px 6px rgba(11,37,69,0.07), 0 1px 2px rgba(11,37,69,0.05);   /* 面板 */
--elev-3: 0 6px 16px rgba(11,37,69,0.09), 0 2px 5px rgba(11,37,69,0.06);  /* 浮层：拖拽中、弹层 */
```

阴影颜色用**藏青**而不是黑：黑色阴影落在冷白底上会发灰发脏。

**三级圆角**：控件 8 / 面板 14 / 外壳 20。子面永远比父面小一号。

## 8. 玻璃：经过实测后全部取消（决议）

按 frontDesign，玻璃只用于「背后有可见深度、且代表一个层」的表面。大屏一度按这条
做成了半透明浮层，但实测问题很具体：

> 底图是**真实路网瓦片**，地名与路名有深色笔画。卡片半透明时这些笔画会透到正文下面，
> 读数字时要跟地图抢注意力。透明度从 0.62 一路加到 0.92 都还有残影，
> 而 0.95 以上已经看不出「通透」，只剩「脏」。

**最终决议：面板一律 `#FFFFFF` 实色，通透感改由「卡片之间的空隙露出地图」来提供。**
这比「卡片本身透」更稳 —— 文字对比度不再取决于背后恰好是什么颜色，
也就不用为每种底图各调一次透明度。

反过来说，「桌面小组件」的感觉是靠**固定的 2px 间隙 + 三级投影**表达的，
不是靠透明度；这样它不会随底图变化而失效。
