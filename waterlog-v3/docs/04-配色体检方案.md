# 配色体检方案（waterlog-v3）

> 体检对象：`web/src` 的两套色板——主应用 `styles/tokens.css`（+ `utils/tokens.ts` 的 hex 副本，供 ECharts/SVG 读）与大屏 `board/theme.ts`。
> 体检时间：2026-10-29。结论：**改前 9 项不合规，改后 37 对全部过线**；另有 4 处「同一颜色背两个语义」的结构问题，本轮改掉 2 处、保留 2 处并写明理由。

---

## 一、方法与工具

### 1.1 真正跑过的两个技能

| 技能 | 实际动作 | 采纳了什么 |
|---|---|---|
| **ui-ux-pro-max**（`nextlevelbuilder/ui-ux-pro-max-skill`，MIT，npm 包 `ui-ux-pro-max-cli`） | `npm i ui-ux-pro-max-cli` → `init --ai universal --offline` → 跑 `scripts/search.py "city flood monitoring operations dashboard" --design-system -p waterlog` | **只采纳它的度量标准**：正文 4.5:1、图形 3:1、焦点可见、`prefers-reduced-motion`、禁用 emoji 当图标。它给的推荐色板是**深色科技盘**（`bg #0F172A` / `accent #22C55E`），与"整页不要暗区"的既定约束冲突，**不采纳** |
| **frontDesign**（`PrayZhou/frontDesign`，component-driven-frontend） | 读 README 六条原则 | 采纳三条：①「Evidence outranks novelty」——先量再改，不凭手感换色；②「保留项目既有基础」——不动版式与令牌命名，只改值；③「渲染后的桌面态要真的看过」——改完必须截图复核，不能只看色值 |

> 说明：`web_search` 在本机不可用（`DEEPSEEK search has no API key`），技能靠 GitHub API 检索、npm 安装、本地执行三步入场；两个技能都不是"读 README 就算用过"，`search.py` 的输出与 npm 安装记录都在。

### 1.2 判据

- **WCAG 2.1 AA**：正文 4.5:1；大字（≥18.66px 粗体 或 ≥24px）与**承担信息编码的图形**（条形、曲线、徽标底）3:1。
- 半透明前景先合成到背景上再算；半透明面板（大屏 `rgba(255,255,255,0.94)`）先把面板压到底图最坏底色（深绿地块）上再算——这样算出来的才是值班员真正看到的那一层。
- 覆盖面：37 对前景/背景，包含主应用正文三层、侧栏三点、四级告警 ink/weak、主按钮三点、智能体标签、中性徽标，以及大屏面板正文三层、五档等级 ink、图形色、预测线、雨强。

### 1.3 复跑方式

```powershell
# 在 waterlog-v3 根目录
python scripts/audit-contrast.py     # 失败时退出码 1，可直接进 CI
```

脚本直接读三个源文件（不读浏览器），所以**改色必经此门**：改了 `tokens.css` 忘了同步 `utils/tokens.ts`，图表与 UI 就会撞色，而这里会先报出来。

## 二、体检发现

### 2.1 对比度不合规（改前 9 项）

| # | 位置 | 前景 | 背景 | 实测 | 门槛 | 影响 |
|---|---|---|---|---|---|---|
| 1 | 主应用三级文字 `--text-3` | `#94a3b8` | `#f1f5f9` | **2.34** | 4.5 | kbd、占位符 |
| 2 | 同上 | `#94a3b8` | `#f5f7fa` | **2.39** | 4.5 | 卡片外副标 |
| 3 | 同上 | `#94a3b8` | `#ffffff` | **2.56** | 4.5 | **时间戳、单位、脚注——全站最广的一处** |
| 4 | 红 ink 落在红弱底 | `#dc2626` | `#fee2e2` | **3.95** | 4.5 | LevelChip 上的"红色预警" |
| 5 | 深色侧栏弱化 | `#64748b` | `#0f172a` | **3.75** | 4.5 | 分组标题、"按研判等级"这类 hint |
| 6 | 大屏脚注 `textFaint` | `#8AA2B6` | 面板 0.92 白 | **2.65** | 4.5 | 刻度、单位、脚注 |
| 7 | 大屏脚注压在深绿地块上 | `#8AA2B6` | 合成后 `#FBFCFA` | **1.80** | 4.5 | 同上（最坏情况） |
| 8 | 大屏"无预警"条形 | `#A9BCCD` | 面板 | **1.95** | 3.0 | 等级环形图里那一段几乎看不见 |
| 9 | 大屏雨强数字 | `#2E9BD6` | 面板 | **3.10** | 4.5 | 雨强是**正文数字**，不是图形 |

**共同根因：亮度阶梯塌了。** 主应用把"三级文字"当成了"更浅的灰"，一路浅到 2.3:1——层次是靠**亮度差**做出来的，而不是靠字号与字重。大屏同理：`textFaint` 为了"不抢戏"压到 2.65，结果压成了看不清。

### 2.2 色相盘点（结构问题）

30 个有彩色令牌跨 7 个 30° 色相桶，但集中度很高：

- **30° 桶挤了 6 个**：黄、橙各有一套 surface + ink，外加 `--warning`/`--warning-ink` **与黄完全同值**。
- **210° 桶 12 个**：`--primary #2563eb` 与 `--level-blue #2563eb` **同值**——"主按钮"和"蓝色预警"是同一个颜色。
- **180° 桶**：`--fc-line #0e7490` 与 `--accent-ai #0e7490` **同值**。

其中两处是真的会误读：

1. **黄色预警与橙色预警色相只差 11.6°**（`#d97706` h=32.1°，`#ea580c` h=20.5°）。在 12px 的 LevelChip 上，黄与橙几乎分不开，而这两档的处置含义不同（黄色=关注、橙色=准备转移）。
2. **主色 = 蓝色预警色**。蓝色预警是"最低一档但确实是预警"，而主色是"可点的操作"，同色会让界面读起来像"到处都有蓝色预警"。

## 三、处置清单（改了什么）

### 3.1 令牌改动（9 个，均带实测）

| 令牌 | 旧值 | 新值 | 旧实测 | 新实测 | 依据 |
|---|---|---|---|---|---|
| `--text-3` | `#94a3b8` | `#66707F` | 2.56 / 2.39 / 2.34 | **5.01 / 4.67 / 4.58** | 保持灰蓝中性，只压亮度到刚好过线，观感变化最小 |
| `--sidebar-muted` | `#64748b` | `#94A3B8` | 3.75 | **6.96** | 深色底上要**提亮**而不是压暗 |
| `--level-red-ink` | `#dc2626` | `#B91C1C` | 3.95 | **5.30** | 原来 red 的 ink 与 surface 同值，是漏改；改成与 `--danger-ink` 一致 |
| `--level-blue` | `#2563eb` | `#0284C7` | — | 图形 4.10 | 与主色分离，蓝色预警改走青蓝 |
| `--level-blue-ink` | `#2563eb` | `#0369A1` | 4.75（贴线） | **5.45** | 同上 + 留裕量 |
| `--level-yellow` | `#d97706` | `#C08A00` | 3.19 | 图形 **3.05** | 色相从 32.1° 移到 43.1°，**与橙色的间距 11.6° → 22.6°**；亮度压到刚好满足 3:1 |
| `--level-yellow-ink` | `#b45309` | `#8A6100` | 4.51（贴线） | **4.98** | 与新的黄 surface 同族 |
| `--warning` / `--warning-ink` | `#d97706` / `#b45309` | `#C08A00` / `#8A6100` | — | 同黄 | 统一到黄，不再维护第二套值 |
| 大屏 `textFaint` | `#8AA2B6` | `#62727F` | 2.65 / 1.80 | **5.18 / 5.03** | 面板半透明，按"压到最坏瓦片上"取 |
| 大屏 `level.none` | `#A9BCCD` | `#8796A4` | 1.95 | **3.03** | 图形门槛 3:1，刚好够；再深会跟正文抢 |
| 大屏 `rain` | `#2E9BD6` | `#257EAD` | 3.10 | **4.50** | 雨强当正文用，必须过 4.5 |
| 大屏 `level.blue` / `levelInk.blue` | `#2563EB` / `#1D4ED8` | `#0284C7` / `#0369A1` | 5.17 / 6.70 | 4.10 / **5.93** | 与主应用同步取色 |
| 大屏 `level.yellow` / `levelInk.yellow` | `#D97706` / `#B45309` | `#C08A00` / `#8A6100` | 3.19 / 5.02 | 3.05 / **5.54** | 同上 |

三处文件都改了：`styles/tokens.css`（CSS 变量）、`utils/tokens.ts`（ECharts/SVG 的 hex 副本）、`board/theme.ts`（大屏色板）。**这是硬约束**：只改 CSS 不改 TS，图表会和 UI 撞色。

### 3.2 两处"用填充色当文字"改回 ink

| 文件 | 位置 | 改法 |
|---|---|---|
| `board/scenes.tsx:584` | 多类别对比右列数值（17px 粗体，未到"大字"18.66px 门槛） | `p.level[lvl]` → `p.levelInk[lvl]` |
| `board/BoardPage.tsx:457` | 顶栏"N 站 红色预警"角标 | `p.level[worst]` → `p.levelInk[worst]` |

黄色 surface `#C08A00` 当正文只有 3.05:1，橙色 `#EA580C` 只有 3.56:1——**它们只能做填充，不能做文字**。这条规则已写进 `tokens.css` 的注释，避免以后再加回来。

### 3.3 两处"不是对比度、但让画面发灰"的问题（大屏）

审计只测"文字看不看得清"，但用户说的"画面还是不行"有一半来自**层次**：

1. **地图瓦片被压到同一个亮度带**：`saturate(0.20) brightness(1.05) contrast(0.92)` 把真实地图压成了米白纸片，与面板、与页底几乎同明度，整页像一张糊了的纸。
   → 改 `saturate(0.32) contrast(1.02)`：街道肌理与水系回来了，但仍比数据色低饱和——**颜色依然只留给数据**。
2. **面板边界靠投影硬撑**：0.92 白面板 + `1px rgba(255,255,255,0.72)` 白描边，等于没有描边。
   → 面板 0.92 → **0.94**、描边改 `rgba(255,255,255,0.98)`，阴影改三层（`0 0 0 1px rgba(12,60,90,0.07)` 发丝环 + 贴地影 + 远处柔影）。
3. 页底 `#EAF3FB` → **`#E4EFF9`**，顶部渐变相应加深一档：让白卡有"浮起来"的参照物。

## 五、还没动 / 不适用

1. **30° 桶仍有 6 个**：`--warning`/`--warning-ink` 现在是 `--level-yellow` 的**别名**（同值同义），不是第二套色。保留它们是因为调用点很多，删了要改 20+ 处，收益不抵风险。
2. **`--fc-line` 与 `--accent-ai` 仍同值**（`#0e7490`）。它们从不相邻出现（一个在趋势图、一个在智能体标签），同色不会误读，本轮不动。
3. **黄/橙 surface 当文字**：3.05 / 3.56，低于 4.5。已把两处调用点改成 ink，并把规则写进注释；没有做全仓扫描式的强制 lint——那属于工程治理，不是配色。
4. **`prefers-reduced-motion` / 焦点环 / 键盘可见性**：ui-ux-pro-max 的清单里也有这两条，但它们不属于"配色"，本轮未动，已记录为后续项。
5. **深色主题**：已在上一轮下线（`PALETTES.dark` 是浅色别名），本次沿用单主题。若以后要恢复深色，本脚本需要补一套 dark 的对子——不要在深色上直接套用这一版数值。
6. **对比度不是全部**：WCAG 只管"看得清"，管不了"好不好看"。本轮把 9 项硬伤清零、把黄橙分开、把层次拉开；若仍觉得不够"高级"，下一步该做的是**留白与信息密度**（去掉冗余标签、把同义数字合并），而不是继续调色值。
