## 1. 项目全貌与职责边界

【事实】`水涝监测软件部分.xlsx` 定义 2 个一级模块、10 个二级模块：

| 归属 | 一级功能模块 | 二级功能模块（序号） |
|---|---|---|
| **对方**（政务既有） | 黄岩区城市内涝基础平台 | 1 平台基础业务 · 2 视频应用及联网管理 · 3 监测设备接入管控 · 4 雨水管网/污水管网/易涝点监测 · 5 监测信息管理 · 6 物联设备运维管理 · **7 内涝底座接口开放** |
| **我方**（本平台） | AI 水位预测及预警平台 | **8 预警功能配置** · **9 AI 水位预测分析平台** · **10 模型应用与调配** |

其中第 7 项「内涝底座接口开放」是对方的**对外供数能力**：物联监测设备与时序数据、取流解码/视频预览/录像回放、区域信息与监控点信息、用户服务/事件订阅/数据字典。我方 3 个模块合计 **23 条功能条款**（预警配置 6 + 预测分析 9 + 模型调配 8）。

### 1.1 职责切分原则（对应本次需求）

> **重合的部分 → 直接按对方接口复用，不自造；不重合的部分（AI 平台独有）→ 由我们自行设计。**

| 能力类别 | 归属 | 处置 |
|---|---|---|
| 用户/权限/部门/门户、数据字典、区域与监控点台账、设备与监测项台账、实时监测与历史数据、设备运行状态、视频取流与回放、录像清单、视频质量诊断、事件订阅、设施报警记录、阈值配置、告警上报、工单/案件 | **重合**（对方模块 1/2/3/4/5/6/7 已具备） | **复用 ICM 原接口**，见 §3。禁止在我方重建一套设备/字典/用户模型。 |
| 雨情场景识别与自适应阈值、多源特征融合与质量治理、多时间尺度水位预测、风险等级研判、滚动修正、预测结果与实测对照、预测任务编排、模型训练/验证/版本/推理、算力与调用管理、在线大模型问答 | **不重合**（我方模块 8/9/10 独有） | **自研接口**，见 §4、§5。基础文档「可直接复用/需扩展」结论与此一致。 |
| 统一鉴权、响应码、分页、时间格式、异步任务、幂等、链路追踪、事件号段、安全合规 | **契约层**（双方共同遵守） | 我方对外接口按约定设计；调用对方时**遵从对方实际口径**（§3.3 有 5 处必须迁就的差异）。 |

## 2. 集成架构

### 2.1 四个方向的数据流

```
                        黄岩区城市内涝基础平台（Infovision iCM V3.0.0）
                 ┌──────────────────────────────────────────────┐
                 │ 资源目录 / 基础设施 / 视频 / 网管 / 事件 / 字典 │
                 └───┬──────────────▲───────────────▲───────────┘
                     │ ①出站复用      │ ④告警/事件回传 │ ③事件订阅回调
                     │ (§3 表一)     │ (§3.4)        │ (需我方提供接收端)
                     ▼               │                │
        ┌────────────────────────────────┴────────────┴──────────┐
        │      AI 平台 · 集成适配网关  /api/aiwater/v1/*          │
        │  协议适配 · 鉴权桥接 · 字段映射 · 幂等/重试 · 链路追踪   │
        └───────┬──────────────────────────────▲─────────────────┘
                │ 内部调用（v3 原生契约，不改）  │ ②入站自研（§4 表二）
                ▼                                │ 基础平台/门户调用
        ┌───────────────────────┐      ┌───────┴────────┐
        │ waterlog-v3 现有服务   │      │ 基础平台 / 大屏 │
        │ Go API :8200          │      │ / 第三方应用    │
        │ Python 引擎 :8201     │      └────────────────┘
        └───────────────────────┘
```

- **① 出站复用**：AI 平台主动调用 ICM 既有接口，取数/取流/订阅事件。
- **② 入站自研**：AI 平台对外提供预测、风险、预警、模型、任务等服务。
- **③ 事件订阅回调**：ICM 事件按 `eventDest` 回调我方，我方须提供**免鉴权但验签**的接收端（§4.2 A-9）。
- **④ 告警/事件回传**：预警判定结果写回对方报警/风险模块（§3.4），实现「向既有监测预警业务模块提供规则判定结果」条款。

### 2.2 为什么必须有适配网关（而非直连或改造 v3）

【事实】两者协议差异（我方现状来自 `api/internal/httpapi/respond.go`、`authmw.go`、`router.go`）：

| 维度 | 基础平台 / 约定 | waterlog-v3 现状 | 处置 |
|---|---|---|---|
| 响应包 | `{code, msg, data}`，`code` 为**字符串** `"0"` | 成功=裸 JSON；错误=`{"error":"..."}` | 网关统一包装/解包，**v3 内部不动** |
| 鉴权 | `Authorization: Bearer {accessToken}` | HttpOnly 会话 Cookie（`app_session`）；引擎侧 `X-Ingest-Token` | 网关做 Token→内部会话/服务身份桥接 |
| 路径 | `/api/{域}/v1/...`（iisrm/resource/video/eventService…） | `/api/...`（无版本段，无域段） | 网关暴露 `/api/aiwater/v1/*`，内部转发到 v3 原路径 |
| 分页 | `pageNo`/`pageSize`，`{total,pageNo,pageSize,list[]}` | 多数接口返回数组/单对象，无分页 | 网关补分页壳与 `total` |
| 时间 | ISO 8601 `yyyy-MM-dd'T'HH:mm:ss.SSSXXX`（带毫秒） | **仿真时钟** 60 倍速（`NowTS()`），与真实时间轴不同 | 网关负责双时钟标注，禁止把仿真时间当真实采集时间外发（§6.3） |
| 错误码 | `0/400/401/403/404/429/500/503` 业务码 | HTTP 状态码 + 文案 | 网关映射 |

【推断】若直接改造 v3 的 `respond.go` 与路由，会破坏已上线的 9 个页面、SSE、审计中间件与 `openapi.yaml`（DELIVERY.md 记录线上验收 PASS 59/FAIL 0）。因此采用**旁路适配层**，v3 主干零改动，风险最低，且符合基础文档「模块化服务 + 接口集成、不强改平台主干」的结论。

> **实现留白**：`EXT-POINT(INTEGRATION): 集成适配网关` —— 本期交付接口契约与映射表，网关实现独立部署单元，可后置。接口签名与错误码已固定，可直接编码。

### 3.3 通用约定中必须迁就对方的 5 处差异

【事实】基础文档「表三 12 条约定」是我方设计的目标口径，但调用 ICM 时以下各点**以对方原件为准**：

| # | 基础文档约定 | ICM 原件实际 | 我方处置 |
|---|---|---|---|
| 1 | `code=0`（数字）表示成功 | **`code` 是字符串 `"0"`**；个别接口（`/api/nms/v1/vqd/list`、`/api/common/v1/dictionary/getByTypeCodeAndDataValue`）返回**数字 0** | 网关做 `code` 归一化：按字符串比较 `String(code)==="0"`，兼容两种类型；禁止仅凭 HTTP 200 判成功 |
| 2 | 响应 `data` 统一 `{total,pageNo,pageSize,list[]}` | 部分接口 `pageNo/pageSize` 出参为 **String**；`/api/nms/v1/vqd/list` 还多出 `totalPage`；R6/R12 无标准分页壳 | 网关补壳并做数值转型；忽略未知字段（向后兼容） |
| 3 | 时间 `yyyy-MM-ddTHH:mm:ss+08:00` | 原件为 `yyyy-MM-dd'T'HH:mm:ss.SSSXXX`（**含毫秒、含时区偏移**），示例 `2024-07-05T00:00:00.000+08:00` | 出站按原件格式生成；入站解析兼容两种；统一按 `Asia/Shanghai` 归一化 |
| 4 | `pageSize` 最大 1000 | R1/R2 原件：`pageNo∈[1,2000000]`、`pageSize∈[1,1000]`；R21 原件：`facilityIndexCodes`/`deviceIndexCodes` 单次 ≤1000。（基础文档备注的「批量 ≤50」「R3 ≤100」属**调用方建议值**，ICM 文档未作硬约束） | 网关内置分页循环，至已取数 ≥`total` 或 `list` 为空；禁止无条件全量拉取，批量上限按建议值保守设置 |
| 5 | 统一 Token 鉴权（获取 accessToken） | **ICM 文档全文未提供应用认证 / Token 获取接口**（见 §8 Q1） | 列为待确认；网关预留鉴权插件位，未确认前不得写死凭据 |

> 补充：R5/R7/R8 依赖 `treeCode`，文档多处写「可通过【获取所有树编码】获取」，但**该接口在文档内只有标题、无接口地址**。可用默认值 `treeCode="0"`（国标树）先行联调，正式树编码待对方补充（§8 Q2）。

### 3.4 方案表漏列、但 23 条功能条款需要的「补充复用接口」

【推断】基础文档表一 12 条偏重「取数 + 视频」，以下 ICM 既有接口能覆盖条款中「复用既有模块」的要求，应一并纳入复用清单，**仍按对方原样调用**：

| 编号 | 用途（对应条款） | ICM 地址 | 关键字段 |

## 4. 自研接口清单（不重合部分：AI 平台独有）

【设计原则】
- 统一前缀 `/api/aiwater/v1/`，`POST + application/json`，响应 `{code:"0",msg:"success",data:{...}}`（**对外用字符串码，与对方口径一致**）。

### 4.3 统一响应码与错误语义

| code | 含义 | HTTP | 处理 |
|---|---|---|---|
| `"0"` | 成功 | 200 | — |
| `"400"` | 参数错误 | 400 | 不重试，修正入参 |
| `"401"` | 未认证 / Token 失效 | 401 | 刷新 Token 后**重放一次** |
| `"403"` | 无权限 / 超出数据域 | 403 | 不重试，记审计 |
| `"404"` | 资源不存在（点位/任务/版本） | 404 | 不重试 |
| `"429"` | 限流 | 429 | 退避后重试，单应用默认 100 QPS |
| `"500"` | 服务内部错误 | 500 | 重试 2～3 次（1s/3s/10s 退避） |
| `"503"` | 服务不可用（引擎挂/算力满） | 503 | 同 500；前端须显示「预测滞后」而非空白 |

异步任务另有业务态：`status=queued/running/success/failed` + `errorCode`（`INPUT_MISSING` / `MODEL_UNAVAILABLE` / `TIMEOUT` / `QUOTA_EXCEEDED`），对应条款 9-9「输入数据缺失与任务异常的状态提示」。

## 6. 关键映射与数据约定

### 6.1 编码映射（我方内部 ↔ 对方）

| 我方（v3） | 对方（ICM） | 说明 |
|---|---|---|
| `siteId` / `site.id` | `indexCode`（设备编码）/ `regionIndexCode`（区域）/ `cameraIndexCode`（监控点） | 建议在网关维护 `pointCode ↔ indexCode` 映射表；v3 的 10 个站点对应对方监测设备 |

| 预警 `id` | `warningId`（我方）/ `alarmId`（对方 R21） | A-20 回传时建立双向关联，便于事件全生命周期串联 |
| 模型 `versionId` | 无对应（对方文档无模型仓库规范） | 自研，属「需扩展」项 |

### 6.2 预警等级映射

| 我方 v3 四级 | 对外三级（约定） | 语义 |
|---|---|---|
| `blue` | `low` | 低风险 |
| `yellow` | `medium` | 中风险 |
| `orange` / `red` | `high` | 高风险 |

> 映射放在**网关**，v3 内部四态机与两道「只降不升」硬约束保持不变（ADR-0004）；对外响应同时在扩展字段保留原始四级，避免信息丢失。风险等级编码须走对方数据字典（R13），不硬编码。

### 6.3 双时钟约定（重要，易错）

【事实】v3 是 60 倍速仿真：业务时间用 `NowTS()`，会话过期用墙钟 `time.Now()`；遥测/预测/预警都排在仿真时间轴上（架构说明 §7.3）。
【设计】对接真实平台时：

- `collectTime` / `monitorTime` / `triggerTime` 等**来自对方的数据必须用真实 ISO 8601 时间**，不得用仿真时钟；
- v3 内部预测结果的 `issuedAt` / `predictTime` 若仍为仿真时间，网关外发时须**显式标注 `timeBasis: "simulated"`**，并禁止将其写入对方的报警时间字段；
- 生产 1 倍速时该机制退化为恒等映射，无需改动。

### 6.4 数据字典统一（约定 8 落地）

需向对方申请/复用的 `typeCode` 清单（**具体值待对方提供《对外数据字典项.xlsx》**，§8 Q4）：
