## 1. 本轮改了什么（两处反馈）

### 1.1 称谓口径统一：全文去除「我方 / 对方」

原稿正文用「我方」「对方」指代双方，读起来像私下沟通，不像交付文档。已按**实体名**统一：

| 原措辞 | 现措辞 | 依据 |
|---|---|---|
| 对方（指 ICM 侧平台） | **基础平台** | 原表 Sheet1 B2 / 集成接口清单 A1 原本就用「基础平台」 |
| 对方（指 ICM 接口文档本身） | **ICM 文档** | 如「属对方文档瑕疵」→「属 ICM 文档瑕疵」 |
| 我方（指 waterlog-v3 / 本方案编制方） | **AI 平台** | 与「基础平台」对仗，且与文档内「AI 水位预测及预警平台」一致 |
| 我方对外接口 | **AI 平台对外接口** | 保留「对外/对内」语义层次 |

共替换 **78 处字符串**（分布在 7 个页签），全文扫描「我方 / 对方 / 甲方 / 乙方 / 贵方 / 我司」**残留 0**。
原表基线内容本身不含这类措辞，因此**未触碰任何原有文字**。

### 1.2 可行性分析页去拥挤

**拥挤的真实原因不是列多，而是同一批信息写了两遍。**

原稿在「AI平台接口可行性分析」新增 H–K 四列，其中 J 列（宽 64）塞进 136 字长文本、K 列（宽 34）塞长句，
而行高被原表的 72px 锁死 → 文字挤成一团；同时右侧还飘着 M/N 统计块，整页总宽 438 字符。
而「功能条款覆盖映射」页**已经有**依赖接口 / 现状 / 落地状态 / 补充动作 四列，属重复。

**改法：把「速查」留在可行性页，把「细节」归到映射页。**

| | 改前 | 改后 |
|---|---|---|
| 可行性页新增列 | H–K **4** 列（宽 22/12/64/34） | H–I **2** 列（宽 22/12），J 列留 3 宽空隙 |
| 长文本承载 | 可行性页 J/K 两列 | 「功能条款覆盖映射」页 F/G 两列（宽 76/40） |
| 统计块位置 | M/N（距表格远，飘着） | **K/L**（紧贴表格右侧，中间隔 J 空隙列） |
| 行高 | 被 136 字文本撑到 90+ | 稳定 **72px**（原表行高），文字不再被截断 |
| 整页总宽 | 438 字符 | **311** 字符（-29%） |

映射页同步重构为 7 列：
`条款号 | 二级功能模块 | 功能条款 | 依赖接口 | 落地状态 | AI 平台现状与补充动作 | 联调 / 验证方式`

「现状与补充动作」列取的是逐条代码核对结论（比原先拆成「现状」「补充动作」两列更完整，23 条中 20 条完全覆盖，
另 3 条按技术标识去重补入 8-5 的 `rainScene/appliedThreshold`、9-6 的 `revision`、9-9 的 `A-21`）。

### 1.3 顺带修掉两处原表遗留缺陷

- **结论块文字被截断**：原表结论正文只有 B 列（宽 62.6），230 字挤在 32px 行高里只能显示 2 行。
  已改为 **B:I 跨列合并**，行高按合并后可用宽度（280 字符）重算 → 7 条结论全部完整显示。
- **新增页注释行被压扁**：4 个新增页的 R1 注释固定 18px，长注释显示不全。
  已改为按整表宽度估算高度 → 注释完整可见。

## 3. 最有价值的发现：表一 12 条里有 9 条字段名与 ICM 原件不符

已逐条写进「集成接口清单」表的 **L/M/N 三列**（ICM 原件入参、原件出参、字段差异与联调注意）。
原方案的 E/F 两列表头已加上「（原方案写法·勿用于联调）」标注。

| 接口 | 原方案写法 | ICM 原件真实字段 | 后果 |
|---|---|---|---|
| R1/R2 监测数据 | `deviceIds` `monitorItemCodes` | `deviceType`（必填）`indexCodes[]` | 必填参数漏传，接口直接拒 |
| R1/R2 监测值 | `monitorValue` | **监测项编码作为动态字段名**（示例 `wl`），R1 为 String、R2 为 Number | 固定 tag 解析必然取空 |
| R3 设备信息 | `deviceType` `regionIndexCode` | `deviceTypes[]` `regionCode` | 类型与字段均错 |
| R4 运行状态 | `battery` `voltage` `signalStrength` | `runningStatus[]{code,name}`（如 `deviceLowPower`） | **三个字段原件根本不存在**，全取空值 |
| R5/R7 区域与监控点 | 无 treeCode | `treeCode`（必填，`"0"`=国标树） | 漏参必被拒 |
| R8 空间查询 | `spatialIndex` | `geometryType`+`longitude`+`latitude`+`distance`(米) 或 `wkt` | 参数不存在 |
| R11 质量诊断 | `cameraIndexCodes`+时间范围 | `indexCodes[]`，**无时间范围入参** | 参数名错 + 查询预期落空 |
| R12 事件订阅 | `callbackUrl` `srcIp` `subscribeId` | `eventDest` `subWay` `eventLvl[]`，**无 subscribeId** | 回调地址字段错；原方案声明的订阅 ID 不存在 |

另外三处硬差异已写进表三新增的「适用范围 / 与 ICM 原件的差异」两列：
`code` 是**字符串 `"0"`**（个别接口是数字 0）· 时间是 `yyyy-MM-dd'T'HH:mm:ss.SSSXXX`（含毫秒含时区）·
**ICM 文档全文未提供应用认证 / Token 接口**（这是阻塞联调的 Q1）。
