## ADR 清单

| 编号 | 决策 | 一句话理由 |
|---|---|---|
| [0001](adr/0001-引擎与API进程分离.md) | 预测引擎与业务 API 分成两个进程 | 训练 90 秒期间 API 必须可用，而重训恰恰发生在最不能不可用的时候 |
| [0002](adr/0002-仿真时钟与墙钟分离.md) | 仿真时钟与墙钟是两种类型 | 60 倍速下仿真时间跑到墙钟前面，混用会产出「页面正常但数字不动」的静默 bug |
| [0003](adr/0003-预测增量而非绝对值.md) | 预测水位增量，不预测绝对水位 | 站点高程差 3.6~16.3m 会主导损失函数；增量以观测为锚，曲线不会与实测断裂 |
| [0004](adr/0004-预警四态与处置两轴分离.md) | 预警四态与处置五态是两条独立的轴 | 「预警已被模型解除」和「现场还在排水」必须能同时成立 |
| [0005](adr/0005-前端五层分层.md) | 前端分五层，页面只做布局 | 一个页面文件里住着五种修改理由不同的东西，改任何一样都要重读 500 行 |
| [0006](adr/0006-阈值与规则分离.md) | 可配置的是规则，不是阈值本身 | 阈值是业务标定（改它要重训），规则是研判策略（改它秒级生效） |

## 阅读顺序建议

**想快速判断这项目做了什么** → [03](03-架构说明.md) 的第一、三、四节（全景 + 一次心跳 + 数据流）。

**想验证它是不是真的** → [02](02-验收报告.md) 第 2 节（模型指标，含三条能证伪的结论）与第 3 节（暴雨演练与四态闭环）。全部数据可复现：`make acceptance`。

**想接手改代码** → [03](03-架构说明.md) 第五节「改动落在哪一层」那张表。它列出了十四种典型需求的落点，以及不该动的地方。

**想加一个接口或一个页面** → 先看 [03](03-架构说明.md) 第七节（鉴权三段式：认证 → 授权 → 审计）。
鉴权写在路由层而不是 handler 里，所以加接口时**漏写 `RequireRole` 是看得见的**；
前端加页面时漏的是 `App.tsx` 里一行 `Route`，不是二十个守卫。

**想改算法** → [01](01-算法链路说明.md)，特别是第 3 节（为什么预测增量）、第 4 节（三因子的两道硬约束为什么只降不升）、第 5 节（修正器的三个设计决定）。

**想改架构** → 先翻 [adr/](adr/)。六条 ADR 里每条都有「被否掉的方案」小节，说明哪些路已经走过。

**想上线** → [02](02-验收报告.md) 第六节「已知边界」和 [03](03-架构说明.md) 第十节。
两份列的是同一批东西：本机级鉴权（`Secure` 没设，必须挂 TLS）、容器化未实测、
webhook 只做过本地 echo、单机 SQLite。**这些不是"待办"，是"现在不承诺"。**

## 两份临时性文档的定位

`01` 与 `02` 是**这个版本的快照**：`01` 描述的算法参数（权重 0.45/0.35/0.20、分档 0.22/0.40/0.60/0.78、饱和 180 分钟）都是可配置的，实际值以 `engine/data/rules.json` 为准；`02` 里的指标数字对应模型版本 `v20261021-050212`，重训后会变。

`03` 与 `adr/` 是**长期有效**的：它们描述的是结构与理由，不随参数变化。
