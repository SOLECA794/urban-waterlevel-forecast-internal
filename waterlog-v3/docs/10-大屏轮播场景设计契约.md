## 一、为什么做轮播，以及做什么、不做什么

### 需求原文

> 「可以把原来的服务器上的那版展示屏幕（它的信息更详细）里面的图表之类的做成轮播页面，你这个作为主页，页面之间做一点自动切换这样的，总之就是内容做丰富一点」

### 拆成三件可执行的事

| 需求 | 落地方式 |
|------|----------|
| 「你这个作为主页」 | 第 0 屏 = 现有的「全域态势」一屏超集（22 个组件），**版面一个字没改** |
| 「服务器那版的图表做成轮播页」 | 新增 4 屏：站点透视 / 多站对比 / 预警统计 / 雨情响应 |
| 「页面之间做一点自动切换」 | 场景轮播引擎：到点自动推进 + 顶栏手动切换 + 暂停 + 进度条 + `?scene=N` 定屏 |

### 明确不做的一件事：不引入第二套皮肤

服务器上 8103 那版（`feature/big-screen` 分支的演播室版）是**深色宇宙 + 地球弧线**。
本次**不把它搬过来**，只搬它的**信息组织方式**。理由三条：

1. **同屏混两套皮肤会跳版**。轮播切屏的那一下，观众看到的是「界面换了」而不是「内容换了」，
   大屏的第一印象就废了。
2. **深蓝版此前评审已判过病根**：11 张白卡按 `384|1fr|384` 铺满 1920×1080，
   只剩 14px 缝隙，背景几乎 100% 被遮挡——「没有前后层次感」不是配色问题，是版面问题。
   搬皮肤等于把那个问题一起搬过来。
3. **浅色天光 + 实色白卡 + 高德浅色底图（style=8）这套已经过了评审**，
   硬约束是「整页不许有暗区」「颜色只留给站点与预警等级」。

所以本轮的视觉主线**只有一条**，五屏共用：
浅色天光底 + 24px 工程网格 + 实色白卡（`color-mix(强调色 9%, 面板白)`）+ 3px 强调色竖条。

## 二、场景契约

### 2.1 五屏回答五个问题

轮播的分界不是「页面」，是**数据类别**。一轮下来观众看到的是同一座城市的五种切片。

| # | key | 场景 | 回答的问题 | 数据类别 | 停留 |
|---|-----|------|-----------|----------|------|
| 0 | `overview` | 全域态势 | 此刻全城怎么样 | 汇总 | 24s |
| 1 | `station` | 站点透视 | 这个站接下来会怎样 | 纵向 | 18s |
| 2 | `compare` | 多站对比 | 该先管哪个站 | 横向 | 18s |
| 3 | `alerts` | 预警统计 | 告警在恶化还是在收尾 | 事件 | 18s |
| 4 | `rain` | 雨情响应 | 雨和积水之间隔了多久 | 成因 | 18s |

一圈 96 秒。主页组件最密、阅读负担最大，所以停留最久——**时长按场景取，不取平均值**。

### 2.2 场景 = 一组组件 + 这组组件各自的坐标

```ts
interface SceneDef {
  key: string
  title: string
  subtitle: string
  durationMs: number
  widgets: 'all' | readonly WidgetId[]
  rects: Partial<Record<WidgetId, Rect>>
}
```

- `widgets: 'all'` = 全部组件可见（第 0 屏，也是「主页」）。
- `rects` 里**没列出的组件沿用当前版面**。于是「切到别的场景再切回来」不会把用户
  在主页手拖好的版面弄丢。
- 第 0 屏的 `rects` 是空对象，完整沿用 `layout.rects`（预设 + localStorage 手拖结果）。

## 三、坐标不是随手填的：每张图有自己的天然比例

大屏里的图全是 `preserveAspectRatio="none"` 的 SVG，**一律拉伸填满盒子**。
这有两层后果：

- 对纯几何图（曲线、柱阵）无害；
- 对**带文字的**图是读错事故：水位曲线被抻高之后，阈值色带的上下沿不再对应真实水位，
  读图的人会以为水位更高。

所以版面尺寸按各图的 viewBox 反推：

| 图 | viewBox | 天然比例 | 版面给的盒子 |
|----|---------|---------|--------------|
| 水位与预测（trend） | 720×330 | 2.18 | 940×430（2.19）✅ |
| 预报全景 / 累计雨量 / 降雨响应 | 100×30 | 3.33 | 宽扁即可，几何图不怕拉伸 |
| 预警构成（pie） | 104px 圆环 + 5 行图例 | ~120 高 | 704×190，横向一行 |
| 站点排行（rank） | 3 维度 × 各 3 条 | 宽而矮 | 704×250 |

> 第 0 屏的 trend 盒子是 465×353（比例 1.32），**是本轮之前就有的状态**，本轮未改动。
> 轮播各屏按正确比例排，是新增的部分。

## 四、切屏动效：两阶段叠化，不做逐组件滑移

### 4.1 做法

```
轮播到点 → 整层淡出（180ms）→ 换版面（坐标 + 可见集合一次换掉）→ 整层淡入（320ms）
```

场景切换由 `BoardPage` 里的两阶段状态机控制，`phase: 'in' | 'out'`。

### 4.2 为什么不做「逐组件滑过去」

逐组件滑过去看着更高级，但**地图瓦片是按最终尺寸一次性算好的**
（`RealMap` 接收 `width`/`height` 两个 props，内部按它们算瓦片网格）。
容器在过渡中被拉伸 → 瓦片没铺满 → 露出半张残缺地图。
与其做半个残缺的地图，不如一次干净的叠化。

### 4.3 不可见组件：不卸载，只淡出

`Widget` 通过 `useSceneRuntime()` 读当前场景的可见集合：

- 不在集合里 → `opacity: 0` + `pointerEvents: 'none'` + `aria-hidden`；
- **不卸载**。卸载会让 SVG 图表重算、地图重新取瓦片，切屏时出现一片空白。

组件自身的淡出用 260ms，比整层叠化略短——观感是「内容先走、幕布再落」。

### 4.4 降级与可访问性

- 尊重 `prefers-reduced-motion` 的场景未做（**未执行项**，见 §7）；
- 轮播有明确的暂停按钮，且 `document.hidden` 时自动挂起计时器；
- 不可见组件带 `aria-hidden`，屏幕阅读器不会读出别的屏的内容。

## 五、轮播引擎的五条纪律

`web/src/board/useRotation.ts` → `useSceneRotation()`。

1. **轮播与数据刷新彻底解耦**。轮播只管「到点换一屏」。反过来做（把轮播绑在请求的 then 上）
   会出现「请求慢了就卡屏」。
2. **不用逐帧 setState 推进度条**。1920×1080 整棵树 60fps 重渲染，在常驻会议室盒子上直接掉帧。
   进度条交给 CSS 动画（`bpProgress`，`key` 变化就重放），每秒重渲染次数从 60 降到 0。
3. **`document.hidden` 时挂起计时器**。否则切到别的标签页后屏已经翻了好几页，回来看是一片陈旧数据。
4. **定屏（`?scene=N`）时不自动推进**，但手动切换仍可用——截图脚本要的就是「定在第 N 屏别动」。
5. **时长按场景取**，不取平均。

## 六、交互契约

### 6.1 顶栏

```
[台标] 台州市黄岩区  [N 个监测站] [降雨中 N 站]     1/5 [全域态势][站点透视][多站对比][预警统计][雨情响应] ▶  全部监测要素 · 值班常驻主屏     [均衡][地图优先][信息优先] [调整布局]   [告警]  时间  ●实时
```

- 场景 chip：当前项实心主色 `#1E6FA8`（`p.accent`），其余描边次级色；
- 播放/暂停用**几何图形**（两根竖条 / 三角形），不用 emoji——字形在不同系统上不可控；
- 副标题取当前场景的 `subtitle`，`maxWidth: 210px` + 省略号兜底；
- 进度条贴在顶栏下沿（top: 60，2.5px），**读作标题栏的下划线**，不是独立控件。

### 6.2 定屏与调试

| URL | 行为 |
|-----|------|
| `/board` | 第 0 屏，自动轮播 |
| `/board?scene=2` | 定在第 2 屏，**不自动推进**，手动切换可用 |
| `/board?edit=1` | 进布局编辑态 |

`?scene=N` 的契约与仓库里既有的 `scripts/shoot-board.mjs --scenes 0,1,2,3` 完全对齐
（该脚本本来就按 `?scene=` 拼 URL，此前是空约定，现已落地）。

### 6.3 布局编辑态与轮播互斥

进「调整布局」时：自动切回第 0 屏 + 停轮播。
理由：预设与拖拽只改主页版面，边转边拖会被场景切换立刻顶掉，用户会以为「拖了没反应」。
点「完成」恢复轮播。
